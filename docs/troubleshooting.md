# 排查问题

先看“传输”中的任务状态和错误提示，记录应用版本、系统版本、任务 ID 与发生时间。按下面对应现象检查。

| 现象 | 检查与处理 | 完成判据 |
|---|---|---|
| APK 覆盖失败 | 核对 Android 版本、arm64 ABI、应用 ID 和签名；使用同签名正式包 | 安装成功，原队列仍可见 |
| IPA 无法安装 | 检查签名、设备 provisioning、iOS 版本和 entitlement | 设备能启动并保存登录凭据 |
| 登录失败 | 地址为 HTTPS 根地址，设备时间与 TLS 正常；请管理员核对实例和当前授权码 | 账户显示已登录，再完成一次上传 |
| iOS Keychain `-34018` | 修复签名和 entitlement；若远端已配对但本机未保存凭据，请管理员轮换实例码后重试 | 登录后能保存并复用设备凭据 |
| 本地照片缺失 | 检查系统照片/视频权限及有限授权范围，返回前台刷新 | 已授权项目显示在本地图库 |
| 自动备份未执行 | 检查登录、媒体类型、相册、Wi-Fi/充电条件和系统后台限制 | 前台任务完成；自动任务在系统允许时运行 |
| 等待重试 | 查看网络和下一次重试，保留已有队列与分块 | 原任务继续上传并取得完成回执 |
| 身份不一致或永久失败 | 保存任务 ID，核对服务器、实例身份和源媒体 | 同一实例下修正问题，或明确取消相关批次 |
| 缓存占用较多 | 使用“清空浏览缓存”，按需要降低缓存预算 | 预览缓存减少，队列与照片原件保留 |
| `StateLockPoisoned` | 关闭当前 session 并重新打开应用/本地数据库 | 重新打开后从已提交记录恢复 |

## 检查网络

在开发机运行，将域名换成实际服务端：

```sh
curl -fsS --max-time 15 -o /dev/null -w '%{http_code}\n'   https://backup.example.com/healthz
```

正常返回 `204`。这确认公开健康入口可达；手机仍需要自身网络可达、有效授权和上传验收。

## Android 日志

电脑连接并获得 USB 调试授权后：

```sh
adb shell dumpsys package org.sarmg.xszc
adb shell pidof org.sarmg.xszc
adb logcat --pid=ACTUAL_PID
```

第一条查看版本与权限，第二条取得当前进程 ID。将 `ACTUAL_PID` 换成非空的实际值；没有进程时先打开应用。Ctrl+C 结束日志。正常停用使用应用“退出”；`adb shell am force-stop org.sarmg.xszc` 是应急终止，后台任务可能要等用户再次打开才恢复。

## iOS 日志

通过 Xcode 的 Devices and Simulators 查看设备崩溃信息，或在 macOS Console 中选择设备并筛选应用。前台重新打开应用，可检查系统暂停后队列是否继续。

## 保留排障信息

分享最小的脱敏错误、版本和任务 ID。照片、授权码、Token、数据库及完整设备日志可能含私密信息。队列与 `prepared` 分块是待传状态；先按[数据维护](operations.md)判断，再处理单项任务。
