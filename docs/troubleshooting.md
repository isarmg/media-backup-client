# 排查问题

先看“传输”中的任务状态和错误提示，记录应用版本、系统版本、任务 ID 与发生时间。按下面对应现象检查。安装、签名和系统日志按 [Android](platforms/android.md#平台排障)或 [iOS](platforms/ios.md#平台排障)查阅。

| 现象 | 检查与处理 | 完成判据 |
|---|---|---|
| 登录失败 | 地址为 HTTPS 根地址，设备时间与 TLS 正常；请管理员核对实例和当前授权码 | 账户显示已登录，再完成一次上传 |
| 本地照片缺失 | 检查系统照片/视频权限及有限授权范围，返回前台刷新 | 已授权项目显示在本地图库 |
| 自动备份未执行 | 检查登录、媒体类型、相册、Wi-Fi/充电条件和系统后台限制 | 前台任务完成；自动任务在系统允许时运行 |
| 等待重试 | 查看网络和下一次重试，保留已有队列与分块 | 原任务继续上传并取得完成回执 |
| 身份不一致或永久失败 | 保存任务 ID，核对服务器、实例身份和源媒体 | 同一实例下修正问题，或明确取消相关批次 |
| 缓存占用较多 | 使用“清空浏览缓存”，按需要降低缓存预算 | 预览缓存减少，队列与照片原件保留 |
| `StateLockPoisoned` | 关闭当前 session 并重新打开应用/本地数据库 | 重新打开后从已提交记录恢复 |

## 检查网络

在开发机运行，将域名换成实际服务端：

```sh
curl -fsS --max-time 15 -o /dev/null -w '%{http_code}\n'   https://backup.example.com/healthz
```

正常返回 `204`。这确认公开健康入口可达；手机仍需要自身网络可达、有效授权和上传验收。
