# Media Backup Client 0.4.0

手动选择照片和视频后创建持久化批次，不再通过自动相册扫描扩大本次上传范围。
Android 使用系统 Photo Picker；iOS 使用 PHPicker，已有 PhotoKit 访问权时导出完整资源，
否则按选择器实际交付的原始文件保存“导入副本”。两端共用现有 Rust 分块队列和 `/v2` HTTP 协议。

云端改为每次最多 100 项的游标分页网格，提供收藏、相册、回收站筛选，独立大图查看、缩放、
左右切换和单项保存。浏览不要求本地相册权限，查看器只写应用缓存。

队列对相同来源版本幂等入队，保留准备好的分块与续传状态；内容变化建立新任务。
批次取消仅撤销该批次的引用，其他批次或自动规则的引用仍有效。完成响应和去重资源清单
写入可核验的回执；原始资源与缩略图独立重试。资料按服务器与账户隔离，并核验实际账户 ID。
所有携带凭据的 HTTP 客户端禁止重定向，资源下载只接受 HTTPS 同源地址。

发行号和 Rust crate 为 `0.4.0`，移动身份为 `media-backup-mobile-v0.4-r1`，
SQLite schema revision 为 `2`，新增 `mb_transfer_v2` / JNI `transfer`，Foundation ABI 保持 v2。
长期偏好与登录账户保存域保持原样，新设备令牌使用独立键重新注册以取得账户、设备 ID。
旧队列不会被读取、改写或悄悄投向新账户；本版本不提供旧状态迁移，离线升级仍归 `sarmg-upgrade`。
当前独立升级工具的 Server 支持矩阵不表示已支持移动队列迁移。

本次覆盖手册三个阶段：两端增加原生本地图库、日期/相册批量选择、多资源备份角标、
未备份/待确认筛选、单项自动排除及缓存设置；增加事务化增量图库缓存、离线已缓存页，
并接入配套 Server 的全库类型/日期/设备筛选、1600 像素预览和视频 Range 读取。
Android 使用 Media3，iOS 使用 AVPlayer 与受控资源加载器。

单原件暂存上限为 2 GiB；图片内存缓存 24 MiB，磁盘默认 256 MiB（可设置 64–1024 MiB）。
第三阶段需要运行本次配套 Server 源码；HTTP 上传 DTO 和服务器数据库 schema 保持现有版本。
原生播放器已接入，iOS Xcode 构建、两端真机视频/后台调度验收仍需在对应设备执行。

验证详情及设备验收清单见 [实施与验收记录](../manual-backup-implementation.md)。
本次工作不创建发行标签、不签名、不发布安装包。

## iOS 安装包格式

iOS Release 附件为 `media-backup-ios-0.4.0-unsigned.ipa`，不再发布 `.app` 的 tar.gz 压缩包。
IPA 内为 `Payload/MediaBackup.app`，使用 iphoneos 真机构建；普通 CI 也上传相同格式。
沿用现有未签名策略，安装前需使用自己的 Apple 签名凭据或侧载工具重新签名。
发布流程校验应用 ID、版本、真机平台、可执行文件及 ZIP 完整性，生成 SHA256SUMS 后作为 Release 附件上传。
