# xszc 1.1.0

本次更新优化 Android 与 iOS 的本地图库和视频播放体验，正式标签为 `v1.1.0`。

## 本地图库

- 全部已授权照片和视频进入轻量目录，连续滚动浏览，取消每 150 项手动加载。
- 使用原生惰性网格，只创建屏幕附近的单元格；日期分组预先计算，刷新沿用稳定的资产 ID。
- 按实际显示尺寸请求缩略图并预取附近项目。Android 使用 32 MiB LRU 缓存及最多 3 个解码任务；iOS 使用 PhotoKit 系统缓存和预热机制。
- 备份状态和来源详情按需读取，浏览缓存上限为 768 项；全选覆盖当前筛选中的全部项目。
- Android 根据 MediaStore 版本和变更编号更新图库，iOS 应用 PhotoKit 增删改通知。授权范围变化时重新核对可访问项目；本地删除不触发云端删除。

## 视频播放

- 点击本地视频直接进入黑色全屏预览，初始暂停，点击播放按钮后开始。
- 移除旧预览页面的白色背景、文件名称、状态文字和自动备份排除文字。
- 本地和云端共用播放控件，提供可拖动进度条、缓冲进度、时间显示及 0.5×–2× 倍速。
- 播放时控件自动隐藏，点按画面再次显示；本地视频使用胶囊按钮选择备份，进入后台或退出时暂停。

## 公共支撑单体和名称规范

- 本次公共输入改为单个 Client 包 `xcsc =1.0.0`，固定官方 Git revision `00770c007912b276f5bb1075abfefe3c31026276`，并与 `Cargo.lock` 一起锁定。原有公共能力物理归入该包的内部模块；移动端使用 `xcsc::mobile_ffi`，Android 启用同包的 `jni` feature。产品自身的 Rust crate 职责保持。
- Client 的依赖图不包含 `xcss` 或 Server 运行时。Server 公共能力和管理 Web 分别由 Server 消费单个 `xcss` 与 `@xcss/web`；客户端只共享独立的业务协议类型。
- 移动状态、队列、配对身份、C/JNI ABI revision 和结果释放规则保留原合同；改包内模块不会自动迁移用户数据，也不要求为这次依赖整理重新配对。
- Android 签名条目 alias 统一为 `xszc-android-release`，受保护 `android-signing` 环境的 Secret 键名为 `XSZC_ANDROID_SIGNING_PKCS12_BASE64` 与 `XSZC_ANDROID_SIGNING_PKCS12_PASSWORD`。仅更改名称，证书和私钥身份保持，证书 SHA-256 为 `0cfc2811d48cdeab3e6d857029d879e001ab9531c06784b4d48d15a847771421`。正式工作流严格检查 alias、唯一 signer、指纹、应用 ID 和原生架构，不接受其他 Secret 名的 fallback。

公共包职责和固定方式见[公共支撑说明](../common-support.md)，签名与发布门禁见[Android 正式签名](../android-signing.md)。本页只保留最新发布说明；历史版本、提交与测试数值继续记录在[依赖和 unsafe 审查](../unsafe-audit.md)，不能作为当前资产验收证据。

## 安装和升级

Android 正式包为 `xszc-android-1.1.0-arm64.apk`，最低 API 26，目标是沿用既有正式签名身份；发布资产通过同一证书及应用 ID 校验后，可覆盖安装 1.0.0。iOS 最低为 26.0，提供 `xszc-ios-1.1.0-unsigned.ipa`，安装前需要使用自己的 Apple 身份签名。两种产物均附 SHA256SUMS。

软件版本升级为 1.1.0，持久状态合同仍为应用版本 1.0.0、SQLite revision 1、`xszc-mobile-v1` 和 ABI v1。保留现有队列、备份回执、配对身份和自动排除规则；配套 Server API 仍为 `/v1`。

## 验证

回归覆盖 10,003 项元数据的全量索引、筛选和按 ID 读取详情，以及增量删除后保留自动排除规则。平台测试覆盖超过 150 项图库的连续滚动、刷新和全选，以及合成视频的默认暂停、播放推进、进度定位、倍速、备份选择和后台暂停。

最终资产必须从精确 `v1.1.0` Source 经 Release 工作流构建，再独立核验 Android 唯一签名证书、应用 ID 和原生架构，以及 iOS IPA 版本和包结构。签名名称迁移和源码门禁通过，不代表本次 APK、IPA 或安装升级已经完成验证；正式结果应以该 Source 的平台 CI、发布工作流与下载资产的检查记录为准。系统权限、实机视频格式兼容性和后台调度仍需要对应设备验收。
